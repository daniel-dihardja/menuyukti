# Scenario Seeding System - Implementation Complete

## Overview

Successfully migrated from hardcoded TypeScript scenarios to a two-stage system:

1. **Python generates realistic data** with proper analytics calculations
2. **TypeScript reads JSON and seeds database** with real matrix/heatmap data from analytics API

## Architecture

```
Python (menuyukti package)              TypeScript (web app)
├─ Generate POS transactions         →  ├─ Read JSON files
├─ Calculate COGS                     →  ├─ Call analytics API
└─ Export to JSON                     →  └─ Seed PostgreSQL
```

## Usage

### 1. Generate Scenario Data (Python)

```bash
cd packages/menuyukti

# Generate all scenarios
uv run python scripts/export_sample.py --scenario thriving_cafe --output-dir seed_scenarios
uv run python scripts/export_sample.py --scenario struggling_restaurant --output-dir seed_scenarios
uv run python scripts/export_sample.py --scenario star_item --output-dir seed_scenarios
```

### 2. Seed Database (TypeScript)

```bash
cd apps/web

# List available scenarios
pnpm db:seed:v2:list

# Seed specific scenario (analytics service must be running!)
pnpm db:seed:v2 star-item

# Seed all scenarios
pnpm db:seed:v2:all
```

## Known Limitations

- ⚠️ Heatmap data requires time-series transactions (not yet implemented in JSON)
- ⚠️ Analytics service must be running on port 8000
- ⚠️ Matrix calculations only (no sales analytics endpoint call yet)

Old system (`db:seed:scenario`):

- Mock matrix/heatmap generation in TypeScript

New system (`db:seed:v2`):

- Data generated by Python with real POS patterns
- Real analytics API calculations
- Production-ready and consistent
